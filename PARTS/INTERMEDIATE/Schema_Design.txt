Q1.

What is the main difference between Embedding and Referencing in MongoDB?
When should each be used?
>> Embedding means storing the data in the one model itself, 
    eg: Storing the address data in the User model itself
    . Referencing means creating separate model and linking with Primary table like Foreign Key
    eg , Users (Primary Table) Orders (Refernce table)

✅ Section B — Practical Modeling
Q3. Design schema for this scenario:

A user in an app can save multiple addresses.
Max addresses = 5 per user.
Addresses are always fetched with user.

Choose Embed or Reference, and give a sample document.
>> I will choose embed , beacuse it only max 5 right
Sample Schema Design
db.createCollection('users',{
    validator:{
        $jsonSchema:{
            bsonType:"object",
            properties:{
                address:{
                        bsonType:"array",
                        maxItems:5
                    }
            }
        }
    }

})

Q4.

A student can enroll in multiple courses
A course has many students
This grows large over time.

Design a schema (collections + fields) and decide embed or reference.

>> I will go with Refernce, beacuse it has lot of courses for students
db.createCollection('students',{
    validator:{
        $jsonSchema:{
            bsonType:"object",
            required:['course_id'],
            properties:{
                name:{
                    bsonType:["string]
                },
                course_id:{
                    bsonType:['objectId'],
                    reference:'courses'
                }
            }
        }
    }

})

                    bsonType:'string'
                },

                    bsonType:'string'
